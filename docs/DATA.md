# 数据格式

工作台只读 `--data` 指定目录。首次启动目录不存在时才复制示例文件；若目录已存在，需包含下列三个文件。

## applications.csv

UTF-8 CSV，每行一个岗位。字段：

| 字段 | 内容 |
|---|---|
| id | 唯一编号，修改状态时保留 |
| market | CN 或 US |
| company / role | 公司名／岗位名 |
| job_id | 岗位编号，多项以 `|` 分隔 |
| status | submitted（已提交）、attention（待处理）、excluded（已排除） |
| applied_at | 实际提交日期，没有就留空 |
| location / url / note | 地点、岗位链接、记录说明 |

不要把准备完成当成已提交。只有真实提交回执或人工确认后才更新为 submitted；工作台不代为判断。

## pending.json

数组，每个问题一个对象：

```json
[{"id":"p1","market":"CN","company":"示例公司","role":"分析师","question":"请确认可到岗日期","created":"2026-01-12T09:00:00Z","resolved":false}]
```

`created` / `updated` 使用带时区的 ISO 日期。已确认时将 `resolved` 更新为 true，并在 profile.json 记录已确认的事实。工作台下一秒更新显示；它不会自动观察聊天并猜测你是否确认。

## profile.json

```json
{"facts":[{"id":"f1","text":"经本人确认的经历"}],"confirmed":{"CN":[],"US":[]}}
```

记录真实资料，不存密码、验证码或浏览器 Cookie。草稿命令会将这个文件作为模型输入，仅使用你明确提供的内容。

## recent.json

后台自动维护最近 **100 次已结束的独立处理**，包括正常完成、中断和结果未确认。记录没有额外按时间过期规则，不要手动编辑。

同一调用编号重复写入只保留一次；不同次真实处理即使动作相同也保留。时间表示该条处理结束的时间。异常原因来自实际记录；无法判断时明确注明未记录具体原因。

升级时会读取旧版 recent.json 和 last_interruption.json，合并已有记录，不清空个人资料或申请表。新异常与正常完成统一保存到 recent.json。具体规则见 [ACTIVITY.md](ACTIVITY.md)。

建议维护程序使用临时文件再替换原文件，避免读取到写到一半的内容。格式出错时界面提示更新中断并稍后重试，不改写原数据。

## 不直接编辑文件的维护方式

项目提供 `python -m career_desk.records --data data/personal`：

- `init`：新建空白个人工作区；已有目录拒绝覆盖。
- `question`：按稳定编号登记或更新待确认问题。
- `answer`：保存本人明确确认的答案，再移除待确认项。
- `application`：按稳定编号新增或更新申请记录；三个状态与页面一致。

完整可复制命令见 [从零搭建指南](START_HERE.md)。每个子命令都支持 `--help`。使用临时文件原子替换，并通过数据目录内的写入锁避免两个维护命令互相覆盖；不要同时让其他程序直接重写这些文件。

网页仍只负责读取和显示，不监听你的聊天；Work 需要在获得本人明确回答后实际执行保存命令。
